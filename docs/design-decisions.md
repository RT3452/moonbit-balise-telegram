# 设计决策记录

## 1. 先分离逻辑报文与信道帧

`Packet`、`BaliseTelegram` 和 `BitVector` 分层表示不同抽象：上层可以构造有语义的 Packet，中层负责 Telegram 包序列，底层负责 341/1023 bit 信道。这样测试工具可以直接验证字段，不必每次都经过码本和校验；接收端也可以在任意层定位错误。

## 2. 未知 Packet 保留原始位串

Eurobalise 的 Packet 集合会持续扩展。解析器遇到尚未实现的 ID 时返回 `Packet::Unknown`，而不是静默丢弃或猜测字段。未知包仍参与长度校验、序列遍历和差异报告，未来增加解码器时不会破坏已有调用方。

## 3. Linking 解析输出三态结果

同一个目标可能不存在，也可能因场景配置重复而有多个候选。`Matched`、`Unmatched`、`Ambiguous` 三态结果把数据问题显式交给上层，避免把错误的 Balise Group 关系伪装成成功链接；正向和反向过顶顺序则独立于报文解析。

## 4. 参考材料只用于核对，不复制实现

字段名称和重复段结构参考公开 ETCS 数据资料，码本和多项式通过公开模型交叉核对；MoonBit 代码、错误类型和测试向量在本仓库独立实现。协议规范不随仓库重新分发，来源、许可证和适用范围集中记录在 `docs/sources.md`。

## 5. 严格检查优先于隐式修复

CI 使用 `moon fmt --check`、`moon info` 加 Git 差异检查，并对 `moon check/test` 使用 `--deny-warn`。当前 Moon CLI 没有给 `fmt/info` 提供 `--deny-warn`，因此以“格式化后工作树不产生差异”和“接口信息生成后工作树不产生差异”表达同等的可复现约束。
